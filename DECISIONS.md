## n2: Built the BatteryScope analytics engine in Sources/BatteryCore/Analytics/ (7 fi…
- **Did:** Built the BatteryScope analytics engine in Sources/BatteryCore/Analytics/ (7 files) with tests in Tests/BatteryCoreTests/Analytics/ (6 files). swift build clean; swift test 97/97 green (29 pre-existing + 68 new). No existing BatteryCore file and no Package.swift touched. Analytics is a read-only struct over SQLiteStore answering the five required questions: (1) drainSeries bucketed battery percent + drain rate in %/hr and W, deriving rate from consecutive samples, excluding charging/AC intervals and sleep gaps (a delta > 3x the inferred median sample interval), exposing gaps as SleepGap for UI shading and per-bucket charging/sleep seconds; (2) topProcesses with helper-process merging (Google Chrome Helper (Renderer) -> Google Chrome, com.apple.WebKit.* and Safari Web Content -> Safari, role parentheticals stripped), summed energy impact, share %, and estimated Wh/battery-points apportioned from measured discharge by energy-impact share, documented as an estimate; (3) categoryBreakdown rolling the same attribution up by ProcessCategory with per-category top-3; (4) batteryHealth with cycle count, max-capacity %, and full-charge + remaining runtime at the median recent drain rate (nil rather than infinite when idle or plugged in); (5) insights, 9 deterministic ranked rules (top process, heavy category incl. background, drain-rate trend with time-of-day, sleep drain, high drain rate, battery health, browser-vs-terminal, mostly-plugged-in, no-data). All math is pure and clock-free; scenarios are seeded into a temp-file SQLiteStore (steady drain, charging interlude, sleep gap, browser-heavy, terminal-heavy, background-heavy) and a 7-day scale test covers ~10k battery + ~20k process rows in under a second.
- **Interfaces:** NEW public API in BatteryCore (all under Sources/BatteryCore/Analytics/): struct Analytics { init(store:options:); init(readOnlyPath:options:) throws; drainSeries(window:bucket:) throws -> DrainSeries; topProcesses(window:limit:) throws -> [ProcessUsage]; topProcesses(window:limit:series:); categoryBreakdown(window:) throws -> [CategoryUsage]; categoryBreakdown(window:series:); batteryHealth(now:) throws -> BatteryHealth?; insights(window:) throws -> [Insight]; report(window:processLimit:) throws -> AnalyticsReport }. Value types: TimeWindow (start/end, .last/.lastHours/.lastHour/.last6Hours/.last24Hours/.last7Days(ending:), midpoint, hours), Bucket (.minute/.fiveMinutes/.fifteenMinutes/.halfHour/.hour/.sixHours/.day, .auto(for:targetPoints:)), DrainPoint (bucketStart/bucketEnd, optional percent/pctPerHour/watts meaning no measurable discharge, percentDrop, energyWh, discharging/charging/sleepSeconds, isEmpty), SleepGap (start/end/percentLost/wasCharging/durationSeconds/hours/pctPerHour), DrainSeries (points, gaps, sampleIntervalSeconds, percentDrained, dischargeWh, discharging/charging/sleepSeconds, overall+median pctPerHour/watts, sleepPercentLost, hasDischargeData), ProcessUsage (name, category, energyImpact, sharePct, estimatedWh, estimatedPercentPoints, peakEnergyImpact, sampleCount, mergedProcessNames), CategoryUsage (category, energyImpact, sharePct, estimatedWh, estimatedPercentPoints, topProcesses), BatteryHealth, Insight (id/severity/title/detail/score, Identifiable), InsightSeverity (info<notice<warning<critical), InsightThresholds, AnalyticsOptions (sleepGapFactor, assumedSampleIntervalSeconds, timeZone, healthLookbackSeconds, thresholds), AnalyticsReport. Also: enum AppNameNormalizer.canonicalName(for:), enum Attribution.processUsage/categoryUsage, enum DrainAnalyzer.analyze(samples:window:bucket:options:), enum InsightEngine.insights(InsightContext), struct InsightContext, struct ProcessTotals, and extension SQLiteStore { processTotals(from:to:), latestBatterySample(asOf:lookback:) } in StoreQueries.swift.
